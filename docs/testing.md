# Test strategy and evidence

Tests must fail on regressions, not just exist under a category name. Consumer Pact success is not live third-party certification. Browser behavior is verified separately from Node V8 coverage.

## Commands

GitHub browser fixtures must follow the `redirect_url` and `setup_url` actually registered by the app. They must not invent a callback from the current page or handoff URL. Unit/integration assertions cover personal and organization registration destinations, fresh-parent reuse of the same setup URL, replay/subject checks, expired handoff recovery, and atomic installation persistence. These are deterministic protocol checks, not a real-account certification claim.

`npm run build:vercel` builds the Vite app and Nitro Vercel functions together, checks emitted Workflow routes and source-only discovery, then copies the functions outside the checkout. A credential-free child process loads the API and Workflow step handlers, checks that each includes Playwright and its runtime assets, and verifies the API fails closed over HTTP without configuration. Playwright is loaded as a native Node package: Nitro traces it for the API, while a post-Workflow build hook includes it in the separately emitted step function. The check is included in `npm run verify`; it does not certify live providers or deployment credentials.

- `npm test`: atomic, characterization and behavior tests using Node's existing test runner.
- `npm run test:snapshots`: compare committed, human-reviewable baselines for all seven flow templates, state actions and WebMCP tool contracts.
- `npm run test:snapshots:update`: explicitly regenerate baselines; inspect the diff and commit only intentional changes. Never run this in CI or to hide a regression.
- `npm run test:coverage`: include every library `.ts`/`.tsx` file, including unexecuted files; emit text and `artifacts/coverage/coverage-summary.json`. This report does not count browser execution.
- `npm run test:pact`: real GitHub, OAuth/PKCE, device, credential, anonymous and A2H consumers against isolated HTTP contract servers; see [boundary limitations](contract-testing.md).
- `npm run test:scenarios`: the isolated-browser ceremony driver against self-hosted provider pages covering sign-in, registration, email confirmation, second factors, consent, device approval, prerequisite ceremonies and the walls that stop an attempt. Page shapes are regenerated per instance from a seed; `SCENARIO_SEEDS` widens the sweep beyond the pinned seeds and `SCENARIO_SEED` replays one. Only inference is substituted, and a green run is not evidence about a live provider. See [auth scenario doubles](auth-scenario-doubles.md).
- `npm run test:flows`: every auth scenario driven through a real browser by the `agent-browser` CLI, recorded to `artifacts/flows/<scenario>/` with its transcript, console and page errors. It runs as its own CI job, separate from `verify`, and uploads its evidence on failure as well as success. Recording is safe only because the pages are this repository's own doubles; the rule that verification retains no raw provider or DOM diagnostics is unchanged, and this runner is never pointed at a live provider. See [auth scenario doubles](auth-scenario-doubles.md).
- `npm run test:e2e`: browser functional, accessibility, WebMCP and packed React/Vue consumer scenarios, plus the auth scenario catalog through a real Chromium. The browser run covers scripted pages and real clicks that the Node scenario runner cannot; one of its tests asserts both runners build the same snapshot from the same markup.
- `npm run test:fuzz`: seeded fast-check properties with shrinking. Replay using `FUZZ_SEED`; increase exploration using `FUZZ_RUNS`. Default: 1,000 examples per stateless/reference property, 500 quoted-template examples and 200 environment-edit sequences.
- `npm run test:chaos`: deterministic transport disconnect/timeout/429/503, malformed payload, uncertain A2H delivery, event retry and remote browser outage scenarios. No production services are disrupted.
- `npm run test:mutation`: Stryker source mutations in method selection, schemas, execution hooks, session environment, encrypted credential storage, the Arazzo executor and Stripe/Supabase service adapters. The TAP plugin runs affected test files; the mutation score gate is 80%. This is a declared critical-module scope, **not** whole-repository mutation coverage. Inspect `artifacts/mutation/index.html` and `mutation.json`; surviving mutants remain visible. Focus the service adapters with `npx stryker run --mutate src/server/services.ts`.
- `npm run test:auth:mutation`: additional focused guards for runtime human-input delegation, device transport failures, native callback/session binding, and verified-email selection/revalidation. Results are in `artifacts/auth-mutation`; this does not replace the broader mutation or verification gates. A second run (`stryker.snapshot.config.mjs`, `snapshot.json`) checks native-label handling by executing the actual browser snapshot callback in Node against Linkedom. This keeps Stryker's coverage helpers in their owning process; they cannot run inside a serialized browser callback. Linkedom lacks native label association, so that fixture supplies the platform property while separate Chromium regressions verify real label association and serialization.
- `npm run test:crap`: rerun all-source coverage, then measure each source function using `complexity² × (1 − coverage)³ + complexity`. Scores at or above 30 fail and remain in `artifacts/crap/report.json`. This uses a **line-coverage variant**, not the original basis-path coverage: TypeScript AST decisions count branches, loops, non-default cases, catches, logical operators, optional chains and parameter/binding defaults; nested functions are measured separately. Same-line functions cannot have precise independent line coverage. Missing/stale source coverage fails closed. The calculator has its own executable regression tests. The threshold follows the [original experimental CRAP metric](https://www.artima.com/weblogs/viewpost.jsp?thread=215899); it estimates maintenance risk, not authentication security.

`npm run verify` recursively discovers Node tests, enforces all-source minimums of 90% lines/statements/functions and 80% branches, runs the actual local Workflow tests and critical-guard mutation gate, builds both library/browser and hosted adapter, and runs browser/packed-consumer tests. Its sanitized runner retains every attempt's command exit codes and counts under `artifacts/verification`; missing, empty, skipped or flaky required results fail. It never retains raw provider, model or DOM diagnostics. The separate broader legacy mutation command retains its declared scope above. Install the supported browser engines (`npx playwright install chromium firefox webkit`); the remote-browser orchestration check uses a real local browser with simulated vendor CDP responses. Browser tests must run against the same checkout as their dev server, because native WebMCP fixtures use checkout-local modules.

Focused commands are `test:integration`, `test:security`, `test:agent`, and `test:workflow`. `node scripts/test.mjs all --inventory` lists every discovered Node test; the separate Workflow files are discovered by Vitest. Sensitive Playwright paths disable trace, screenshots, video, HAR and ordinary automatic failure DOM/ARIA snapshots. All browser specs import `tests/fixtures/browser-test.ts`: it strips matcher-supplied snapshot metadata before artifact writing because the installed Playwright version bypasses its opt-out for missing-element assertions. Failures and their source locations remain intact. An intentional-failure regression checks both assertion paths in Chromium, Firefox and WebKit, and rejects specs that bypass the shared fixture. This does not redact arbitrary assertion messages; fixtures must still use synthetic credentials and avoid secret-bearing comparisons. See [teaching release evidence](implementation-evidence/ceremony-teaching/README.md) for current commit-bound results and explicit live/device gates; older checkpoints below are historical, not current certification.

Renewed Jira assignments use distinct notification records while old and new readers retain the same run lease; same-assignment legacy retries preserve their exact signed message. The reviewed retention mutation scope kills all 24 mutants (`artifacts/security-mutation/jira-retention-reviewed.json`); the initial five surviving mutants remain recorded separately.
- Registration journals are staged immediately before the first credential-bearing request, not before opening the provider. Definite username/email rejection clears only the bound rejected attempt; uncertain outcomes retain recovery credentials. Automatic username replacement applies only to handles generated by that attempt, never supplied or vault credentials, and preserves the selected email.
- The browser's bounded inspection retry covers both snapshots and authenticator checks. A navigation interrupted between those checks no longer discards an otherwise recoverable registration.
- DPoP algorithm advertisement is capability, not a requirement. PAR retains the same proof key through token exchange; an actual DPoP requirement fails closed when unsupported or when a bearer token is returned. The reviewed collision/DPoP scope kills all 37 mutants without timeouts (`artifacts/auth-mutation/collision-dpop-policy-refactor.json`).
- Discovery preserves explicit ports and does not infer ownership from the last two domain labels. Its reviewed 50-mutant scope kills all 50 mutants (`artifacts/auth-mutation/discovery-app-reviewed.json`).
- Studio clears a previous provider's run when switching connectors while retaining same-provider progress. Bare `delete` uses the current conversation's provider and removes only its local connection; it makes no provider-account deletion request.

The complexity refactors preserve the runtime's effect order and retain all-source coverage and CRAP thresholds. Their focused before/after checks are not a repository-wide pass; full integrated verification must run after updating from `main`.

## Sources

[Verify](https://github.com/VerifyTests/Verify) describes the approval-baseline workflow. [Node's native snapshot testing](https://nodejs.org/api/test.html#snapshot-testing) provides that workflow in this project's runner: commit serialized baselines, compare on normal runs, and update explicitly after review. No additional snapshot framework is required.

[fast-check](https://fast-check.dev/docs/tutorials/quick-start/) generates and shrinks counterexamples; property assertions use an independent invariant or model, not a copy of the production algorithm. JSON round trips compare JSON semantics because JSON normalizes negative zero. The narrow `typed-rest-client` → `qs` override fixes a vulnerable pinned mutation-tool dependency; a clean install must pass `npm audit`.

[Stryker's TAP runner](https://stryker-mutator.io/docs/stryker-js/tap-runner/) supports the existing Node runner and per-file coverage selection. [Stryker configuration](https://stryker-mutator.io/docs/stryker-js/configuration/) documents score gates, timeouts and reports. Neither line coverage nor a timeout alone establishes correct authentication behavior; review actual killed/surviving mutants and behavioral assertions.

# Agent integration

The server-only AI SDK `ToolLoopAgent` proposes registered node advancement. It cannot supply credentials, bindings, endpoints, verifier code, tenant identity, or an approval. `ProtectedCommandService.advance` loads the pinned plan and rechecks host authorization; UI and agent execution use that authority service. Native WebMCP remains an optional transport, not an authentication mechanism.

Hosts can register connection entry points through `createTeachingRuntime({ connections })`: a read-only map from connector ID to its deterministic `definition`, verified `outputContract`, and host-policy `revalidateOperation`. Omitting the map preserves the GitHub default; an explicit map advertises only its registered IDs. Registration is server configuration, not an imported recipe or model capability. Each operation must still match the host-derived provider/profile and pass command authorization. The capabilities, Connect, and agent routes use this same registration. Published-recipe execution accepts `connectorId` (omission preserves the existing GitHub HTTP contract). Registering an ID does not implement its provider operations, human collector, or certify a live connection.

`CEREMONY_MODEL_URL` remains a full OpenAI-compatible `/chat/completions` endpoint; `configuredModel` explicitly adapts it to the installed provider SDK base URL. `CEREMONY_MODEL` is required when enabling a model; `CEREMONY_MODEL_KEY` is server-only. Gateway is enabled only by explicit trusted configuration, with an explicit model ID. No configured model means no paid service fallback. Model redirects are forbidden for compatible endpoints.

`AgentCoordinator` reserves durable per-run/per-turn budgets before inference. The defaults allow 16 model calls and 64 requested tools per run, eight requested tools per turn. Unknown tool names count. Existing complete access, human waits and absent model configuration require zero model calls. Stopping the assistant is persisted and checked before later tool execution; it neither cancels the connection nor revokes provider access. An interrupted turn with uncertain completion is not silently replayed as a fresh turn.

The Vercel Workflow carrier (`src/server/agent/workflow.ts`) uses `use workflow` and `use step`, with a human-wait hook established before each bounded turn. The Nitro host must load `workflow/nitro`; ordinary Vite rendering is unchanged. The workflow history receives run/turn correlation IDs and enum statuses only. Each step creates a worker-owned hosted runtime, restores the recorded initiating actor and current delegation, invokes the same coordinator, and closes its database pool. A hook wake carries `{wake:true}` only and never substitutes for verified provider evidence or current domain authority. Hosted routes must authenticate and authorize the intended run before waking a hook; failed delivery remains pending for durable outbox retry. Domain persistence, effects, revisions, and continuation delivery remain authoritative, not Workflow replay history.

There is no narration or attachment recorder. `validateAgentText` is a bounded pre-egress utility for hosts adding text input: it rejects known protected values and recognizable credential formats without retaining them. This heuristic cannot detect every arbitrary password. Never add protected fields to model context merely because a user opens an assistant. The model receives positive-allowlist domain snapshots; each model step rebuilds its context rather than appending arbitrary model/tool-error history. Free-form model output is not rendered as an authorization verdict. AI telemetry is disabled additionally, not used as the privacy boundary. Configured model/gateway processors may retain the permitted context under the host's processor policy.

The local SDK transport tests use a real HTTP chat-completions fixture, including unknown tools, malformed responses, structured authoring, outage and durable stop/budget cases. The installed Workflow compiler/local runtime test traverses real PostgreSQL, the hosted runtime, model HTTP, and GitHub preparation; it waits on a durable hook, resumes after stopping the assistant, and verifies the connection remains active with no extra inference. A separate missing-configuration test fails closed. These do not establish process-crash recovery across a deployed platform, live model, hosted Workflow deployment, or attended provider certification. No Eve, Chat SDK, external bot, DOM agent, recorder extension or second agent runtime is installed for this capability.

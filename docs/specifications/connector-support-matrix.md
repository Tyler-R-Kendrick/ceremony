It is produced by `node --import tsx scripts/connector-support-matrix.ts` from three sources: the registered adapters themselves (each factory is constructed with no host configuration and its own `capabilities(present)` rows are read), the swarm ledgers under [`ledger/`](../implementation-evidence/connector-interoperability/ledger), and the [source lock](../implementation-evidence/connector-interoperability/source-lock.json).

Read it with three rules in mind.

- **A dimension is not a boolean.** `implemented` means code exists and is exercised. `requires-configuration` means implemented but not usable in a deployment that lacks the named configuration. `unsupported` is a reported negative capability, and the limitation column says why.
- **Evidence is not certification.** Every level below is `unit`, `protocol-fixture` or `local-integration`. No live vendor credential exists in this environment, so no row anywhere claims live or vendor-certified behaviour. A loopback double proving wire correctness is not a provider's endorsement.
- **Rows are measured with no configuration present.** `capabilities(new Set())` is what a fresh deployment sees. A dimension shown as `requires-configuration` becomes usable once the named configuration is supplied and the host approves a binding, not before.

## Native limitations, as each adapter reports them

### `a2a` — A2A agent

Module: `src/server/connectors/providers/a2a/index.ts` (`createA2aAdapter`).

- discover: A2A defines no agent directory; cards arrive by upload, by registry import or from a configured URL fetched by the host importer.
- import: 0.3 cards are read into the same description; delegation still requires an interface on a supported version.
- authorize: A configured service credential, not a human sign-in: there is no A2A authorization flow to run on a person's behalf.
- verify: Verification compares the served card with the reviewed card and confirms the agent accepted this deployment's credential; it establishes no operator identity and no scope.
- invoke: A2A work is delegation, not invocation: use the delegate dimension so task identity, cancellation and input-required are modelled.
- events: Push notification configuration is not registered; task progress is polled through an approved status operation.
- reconnect: Reconnect re-reads configuration and re-verifies the card; the command layer advances the generation, which fences every task issued before it.
- disconnect: Local disconnect only: A2A publishes no connection resource to delete and no grant to revoke.
- revoke: A2A documents no revocation operation; a local disconnect is not upstream revocation.
- export: This deployment publishes no Agent Card of its own, so there is nothing to export as one.
- delegate: 0.3 method names (message/send, tasks/get, tasks/cancel), lower-hyphen task states and kind-tagged parts; never mixed with the 1.0 wire.

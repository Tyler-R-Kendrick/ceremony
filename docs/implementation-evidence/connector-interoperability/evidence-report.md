## The honest summary first

- **No live or vendor-certified evidence exists anywhere in this work.** There are no authorized vendor credentials in this environment. Every adapter's evidence is `unit`, `protocol-fixture` or `local-integration` against loopback doubles written from published documentation. A double that enforces a documented contract is good evidence of wire correctness and no evidence at all about a real account.
- **Forwarded-delivery verification for Vercel Connect triggers is deliberately incomplete.** Vercel's documentation states that Connect signs the request it forwards and publishes a per-connector signing key, but does not publish the outbound header name or algorithm. `verifyForwardedDelivery` therefore takes the forwarder's verifier as an injected dependency, and the verifier used in tests is a stand-in — not a claim about Vercel's wire format.
- **One provider's webhook verification uses a separate signing key.** Nango's `X-Nango-Hmac-Sha256` is an HMAC-SHA256 over the raw body keyed with the environment **webhook signing key**, which is a different secret from the Environment API key; the legacy plain-digest `X-Nango-Signature` is documented as not to be used and is ignored even when it is correct.
- **Several providers document no pagination for particular list endpoints.** Nango's `GET /integrations` and Supabase's `GET /v1/organizations` and `GET /v1/projects` are the recorded cases. Those adapters window one bounded response and report the absence as a discover issue rather than inventing page parameters.
- **The MCP registry adapter reports `provider-backed`, not `catalog-only`.** It genuinely implements discovery, import and export against a registry. The catalog-only boundary is reported per dimension instead: every execution dimension is `unsupported` with the limitation "execution requires an MCP binding".

## Native limitations reported by the delivered work

Every limitation any ledger recorded, kept verbatim. These are the boundaries an integrator inherits.

- **INT-02** (INT)
  - The reference server's connector actor is derived from its anonymous session cookie; a deployment authenticates before the route table is reached, which is why the handler takes an actor rather than deriving one.
  - No adapter is configured in the reference server, so every provider-backed row reports unconfigured. That is the honest state for a server that has signed up for nothing, not a missing implementation.
- **INT-04** (INT)
  - The consumer is built by unpacking the tarball rather than by npm install: installing pulls runtime dependencies from a registry and one postinstall downloads a native binary, which this environment cannot reach. So the export map and the published file set are proven; the dependency set a fresh install would produce is not.
- **INT-05** (INT)
  - PR #39 is another author's open pull request and was not merged, rebased or pushed to. The reconciliation is an audit recorded in docs/connector-directory.md and a replacement surface on this branch; whether to close #39 is its author's decision.
- **INT-06** (INT)
  - Mutation testing over the connector guards is not wired: stryker.security.config.mjs has no connector guard targets yet, so the killers run in the ordinary security suite but no connector guard is mutated.
  - Live and deployed oracles are all blocked. No authorized credential and no operator consent exists here, and nothing is labelled live.
- **CON-01** (CONTRACT)
  - Contracts validate description shape only; no adapter, transport or persistence behaviour is proven here
- **CON-02** (CONTRACT)
  - Round trips are exercised against real v1 projects built in-process; no HTTP import/export route is involved at this layer
- **CON-03** (CONTRACT)
  - The schema proves a claim's shape and internal consistency; whether an issuer actually observed what it reports is an adapter and command-layer obligation
- **CON-04** (CONTRACT)
  - Canaries are asserted absent from projection output; server-side logging, error bodies and storage are other swarms' surfaces
- **CON-05** (CONTRACT)
  - The refinement constrains how an issue may be reported; it cannot verify that an importer classified a construct correctly
- **CON-06** (CONTRACT)
  - JSON Schema checks structure only; every cross-field refinement is runtime-only and is asserted as such in CON-06-04
- **IMP-01** (IMPORT)
  - YAML is read only as YAML 1.2 with the core schema. An explicit %YAML 1.1 directive is refused rather than reinterpreted, because 1.1 changes the meaning of unquoted yes/no/on/off and of sexagesimal scalars.
  - Explicit !!binary, !!timestamp, !!omap, !!set and !!pairs tags are refused even though the library could resolve them: a connector description has no use for them, and silently keeping the text of an unresolved tag is the reinterpretation import must not do.
  - Merge keys (<<) are refused rather than applied; a description that relies on them must be flattened upstream.
  - A document is one YAML document; a multi-document stream is refused instead of silently using the first.
- **IMP-02** (IMPORT)
  - An end-to-end connection to an administrator-approved private origin cannot be demonstrated offline: a loopback fixture binds to 127.0.0.0/8, which classifies as loopback, not private. The approved-private path is covered by policy assertions plus a DNS-level assertion that an approved origin reaches the transport while an unapproved sibling is refused at the lookup.
  - Request bodies must be fully buffered (bounded by maxRequestBytes); stream and multipart bodies are refused, because neither can be bounded up front nor replayed across a validated redirect.
  - TLS certificate pinning is not part of this fetcher; it inherits the platform trust store through undici.
- **IMP-04** (IMPORT)
  - Only JSON pointer fragments resolve. A plain-name fragment ($anchor, #Pet) and a JSON Schema $id-relative base are reported as unsupported rather than guessed at.
  - $id/$anchor rebasing within a document is not implemented; documents are addressed by the identity they were registered under.
- **IMP-05** (IMPORT)
  - The security classification is pointer-pattern based and covers OpenAPI 2/3, AsyncAPI, Arazzo sourceDescriptions and MCP server.json packages/remotes. A format whose security semantics live elsewhere needs its rule added; unmatched changes are reported as structural, never dropped.
  - Array comparison is positional, so a reordered servers list reports changes at the moved indexes rather than as a move.
  - AC-IMP-06 is covered here only for the source-diff half; overlay application belongs to the FORMATS swarm.
- **IMP-06** (IMPORT)
  - These are pure helpers over ports. HTTP routing, CSRF/origin checks and multipart decoding are the COMMAND swarm's; importUpload takes bytes that the host has already bounded.
  - detectDocument recognizes the family and version only. Normalization into a NormalizedDefinition is the FORMATS swarm's, so every result currently returns empty definitions and executableCandidates.
- **HTTP-01** (HTTP)
  - Readers take an already-parsed document; bytes-to-object parsing (JSON/YAML bounds, duplicate keys, dangerous tags) belongs to the IMPORT swarm. The adapter's default parser accepts JSON only and re-serializes to strip prototype keys.
  - External $ref resolution happens only through the caller's resolveExternal hook; without one, constructs behind an external reference are reported unresolved and blocked, never guessed.
  - Reference fragments are RFC 6901 JSON pointers only; plain-name anchors, $anchor, $dynamicRef and $recursiveRef are refused rather than approximated.
  - 3.2 additionalOperations and QUERY operations are read and preserved, but no non-standard method can be bound (see HTTP-03).
  - Examples, defaults and credential-named vendor keys are dropped from preserved extensions at the import boundary; a vendor extension with a neutral key that embeds a secret in an unnamed field would still be preserved for reviewers.
- **HTTP-02** (HTTP)
  - An openIdConnect issuer is derived only when openIdConnectUrl ends in the standard /.well-known/openid-configuration suffix; any other spelling becomes an unsupported profile with a blocking issue rather than a guessed issuer.
  - mutualTLS is preserved as a mutual-tls profile but blocks authorization: this runtime holds no client certificates.
  - The OAuth implicit and password flows are preserved as unsupported profiles with blocking issues (RFC 9700); no usable credential path is invented for them.
  - The device authorization flow exists only in 3.2; the same flow object under 3.0/3.1 becomes an unsupported profile with a blocking security.unknown-flow issue.
- **HTTP-03** (HTTP)
  - Executable subset: application/json (and +json) request and response bodies; path and header parameters style simple; query parameters style form with explode honoured and allowReserved respected; primitives and arrays of primitives only.
  - Blocked with serialization.* issues: multipart, form-urlencoded, XML, streaming and any other media type; cookie parameters; 3.2 querystring parameters; parameters described by content; deepObject, spaceDelimited, pipeDelimited, matrix and label styles.
  - Schema subset validated: type (including 3.1/3.2 type arrays and 3.0 nullable), enum, const, required, properties, items, additionalProperties, min/max length, items, properties, numeric bounds, multipleOf, uniqueItems and basic formats. allOf/anyOf/oneOf/not/if-then-else, pattern, patternProperties, prefixItems, contains, unevaluated*, discriminator and dynamic references block the operation that uses them.
  - A pure $ref alias cycle (A -> B -> A with no concrete schema) is reported as an unresolved reference and blocks that operation; a structurally recursive schema (a node containing itself) compiles into a named definitions table and validates to an explicit depth.
  - Only the seven methods the binding contract carries can be bound; 3.2 QUERY and additionalOperations entries stay discoverable but block with structure.unsupported-method.
- **HTTP-04** (HTTP)
  - A path parameter value containing '/' is refused (openapi.path-parameter-encoded-slash): %2F containment inside the approved prefix cannot be proven across intermediaries.
  - Credentials come from ctx.environment.credentials.use only. The adapter reads apiKey/username/password/accessToken (optionally suffixed ':<profileId>' when several profiles are presented together); the integrator's credential layer must write those names.
  - Bound authentication profiles are read from binding.settings['openapi-http-profiles']; an alternative naming a profile the binding does not carry fails with configuration-required rather than falling back to another alternative.
  - Verification is available only when the host names an approved read operation as verifier, and it claims credential-accepted against the destination origin — never account identity.
  - No upstream disconnect or revoke exists in an OpenAPI description; both report local scope only and 'unsupported' upstream.
  - Events are unsupported in this adapter: webhooks and callbacks are imported as descriptions, and verified delivery belongs to the events profile.
- **HTTP-05** (HTTP)
  - The JSONPath subset is: root ($), child by name (.name and ['name'] / ["name"]), wildcard (.* and [_]), recursive descent (..name and .._) and non-negative array index ([0]). RFC 9535 filters, scripts, unions, slices, negative indexes and function extensions are refused with a blocking structure.unsupported-selector issue rather than approximated. The Overlay specification requires full RFC 9535 for interoperability, so this is an explicit, documented subset, not a conformance claim.
  - Selection, merge depth, action count and update size are bounded; exceeding a bound refuses the whole overlay rather than applying part of it.
  - A document that cannot be serialized within bounds (for example one whose shared references expand exponentially) is refused with structure.document-too-large instead of throwing, and an overlay's own update or copy value that cannot be cloned within bounds -- oversized, or cyclic as a YAML alias cycle produces -- is refused with structure.update-too-large, leaving the input document unchanged.
- **HTTP-06** (HTTP)
  - Export emits OpenAPI 3.1 only; a document imported as 2.0, 3.0 or 3.2 is republished in 3.1 spelling and the version change is part of the loss report.
  - Response schemas are emitted as permissive (`true`) rather than reproduced: the compiled subset keeps request schemas for validation but does not validate responses, and publishing a response schema the runtime does not enforce would overstate the contract.
  - Without a binding the export carries no operations at all, because no executable surface has been approved.
  - Native extensions are withheld unless the operator explicitly asks for them.
- **WF-01** (WORKFLOW)
  - readArazzo takes an already-parsed JSON value; bounded JSON/YAML text parsing belongs to the import pipeline (IMPORT swarm) and is applied again here through measureJsonValue before interpretation.
  - Non-x- fields the specification never defined are preserved and reported as warnings rather than rejecting the document; fields defined only by a later Arazzo version are blocking.
  - Workflow input JSON Schemas are preserved inertly: they are never compiled, expanded or used to validate runtime inputs (the registered operation contract does that).
- **WF-02** (WORKFLOW)
  - Executable profile only: parallel semantics, goto branching, conditional end, failure goto, channel/async steps, payload replacements, querystring parameters, non-JSON request bodies, selector objects, embedded {$...} templates and pointer extraction inside bindings are preserved and blocked, never approximated.
  - A nested workflow across documents requires the host to have published that workflow as a recipe and registered it in the catalog; there is no cross-document Arazzo resolution.
  - compileArazzoToRecipe compiles one named workflow per call; a document with several executable workflows is compiled once per workflow.
- **WF-03** (WORKFLOW)
  - Only `simple` criteria are evaluated. regex, jsonpath and xpath criteria are parsed for their embedded expressions, preserved and blocked; this runtime implements none of those languages.
  - $request, $message, $response.body, $response.query, $response.path, $self, $workflows and $components resolve to no runtime value; they are recognised by the grammar and refused by the evaluator.
  - Arazzo's `[]` index and `.` property-dereference operators inside a condition are not implemented; a value is reached with an RFC 6901 pointer on the expression instead.
- **WF-04** (WORKFLOW)
  - reviewArazzoImport reports the studio projection; it does not write a ConnectorProject. Assembling a project (manifest, templates, method contracts) around the reviewed workflow document stays with the studio.
  - exportArazzo writes a JSON value; YAML serialization is not implemented.
  - A 1.0.1 to 1.1.0 export changes only the version string and records an info-level note; it does not migrate constructs into 1.1.0 forms.
- **WF-05** (WORKFLOW)
  - The provider is a loopback HTTP fixture on an ephemeral port; no live provider evidence is claimed.
  - Compiled successCriteria, retry policy and timeouts are carried on CompiledStep for the host to enforce; ProtectedCommandService's own verifier/fence/abort machinery is what the tests exercise, and no new retry loop was added to the command service.
  - Cross-surface HTTP mounting of a compile-and-run route is not included; the integrator owns teaching-http and hosted routes.
- **EVT-01** (EVENT)
  - Channels, messages and operations become event descriptors only; an AsyncAPI operation is never compiled into an HTTP capability, so capabilities is always empty for this ecosystem.
  - transport "http-webhook" is claimed only for an inbound operation whose every declared protocol is http/https; ws, wss, kafka, amqp, mqtt, googlepubsub and every other binding keep transport "unsupported" with nativeTransport preserved. No broker runtime is implemented.
  - Only local JSON-pointer $ref resolution; an external or cross-document reference is reported as structure.unresolved-reference and never fetched.
  - Message payload schemas are preserved by reference (messageSchemaRef) rather than expanded, so a recursive schema is bounded by construction.
  - Channel parameters, reply objects and correlationId are preserved only inside the document-level native extension, not as first-class descriptor fields.
  - Perspective (consumer vs provider) is an explicit option; it is never inferred from operation or channel names.
- **EVT-02** (EVENT)
  - toCloudEvent maps only id, source, type, time, datacontenttype and data. receivedAt is custody time, not occurrence time, and is never emitted as `time`; verification, connectionRef and forwarderHops have no CloudEvents attribute and are not smuggled in as extensions.
  - fromCloudEvent returns an explicitly UnverifiedEvent (no verification, no authority): a CloudEvent carries no proof, so reading one can never produce a verified envelope. Mapping `source` to a configured authority is a host decision.
  - CloudEvents binary mode (data_base64) is refused with ConnectorError("unsupported"); only the JSON event format is supported.
  - Only specversion 1.0 is accepted.
- **EVT-03** (EVENT)
  - Only the symmetric v1 scheme (HMAC-SHA256) is implemented. The asymmetric v1a (ed25519) scheme is recognized and reported as "unsupported-scheme" rather than silently ignored; whsk_/whpk_ keys are not handled.
  - Timestamp tolerance defaults to 300s and is bounded to 1..86400s in both directions; a host cannot configure the window away.
  - verifyHmacHeader covers the common HMAC-over-body (optionally over `${timestamp}.${body}`) vendor pattern. A provider whose scheme differs implements VendorVerifierPort directly; nothing guesses a header name or algorithm.
- **EVT-04** (EVENT)
  - No exactly-once claim. A handler that succeeded but whose fence was superseded, or whose outcome could not be recorded, leaves the entry pending, so a consumer may see the same authority-scoped deliveryId again (with the same attempt number) and must deduplicate on it. This is asserted, not hidden, in the PostgreSQL concurrency test.
  - A contended lease (PersistenceConflict, or a PostgreSQL deadlock on the shared claims table) is counted as `skipped` and retried on the next pass; nothing has been delivered at that point, so no effect can be lost or duplicated by skipping.
  - A handler that succeeded but whose delivery commit lost to concurrent writers (a revision conflict on the shared ordering watermark, a lost fence, or a PostgreSQL deadlock/serialization failure, which the store reports only as an opaque persistence error) is retried once immediately under the same fence; if that also fails it is reported as `retried` with outcome `retry`, its claim is released and it is redelivered on a later pass. It does not consume one of maxAttempts and is never parked as failed for it; only handler errors are counted. Because the store does not distinguish a transient persistence error from a persistent one, a commit that can never succeed is redelivered on every pass rather than parked.
  - Ordering is decided from the sender's sourceTime against a per-(authority, connection) watermark. An envelope with no sourceTime is "unknown" ordering and is applied normally.
  - The dispatcher reconciles only deliveries that carry a lifecycle signal; a non-lifecycle event arriving out of order is applied, because its payload is not a status claim.
- **EVT-05** (EVENT)
  - The receiver requires a registered VendorVerifierPort for any non-Standard-Webhooks subscription; an unregistered verifier fails closed with 401 and audit reason "verifier-unavailable". There is no fallback scheme.
  - The delivery identity must come from the verifier, a policy.identify hook or a top-level `type`/id in the payload; an event that cannot be identified is refused 400 rather than given an invented id.
  - The receiver only admits. Applying a lifecycle event to a connection is the COMMAND swarm's dispatch hook (CompletionInput { kind: "event" }); lifecycle mapping here is a hint carried on the delivery.
  - Body ceiling is 256KiB by default, enforced while streaming (a content-length hint alone is not trusted).
  - Only JSON content types are accepted (configurable); form-encoded provider webhooks are not supported.
- **EVT-06** (EVENT)
  - Vercel's outgoing trigger signature header name and algorithm are not published in the Connect triggers documentation (it states only that Vercel signs the forwarded request and publishes a per-connector signing key). verifyForwardedDelivery therefore takes the forwarder's VendorVerifierPort as an injected dependency; the VERCEL swarm supplies the concrete header/algorithm from its own source. The fixture verifier used in tests is explicitly a stand-in, not a claim about Vercel's wire format.
  - The original provider's hop is verified only when this deployment holds that provider's secret (material keys prefixed `upstream:`); otherwise no provider hop is recorded at all rather than an assumed one.
- **OA-01** (OAUTH)
  - Exact issuer comparison only: no trailing-slash or case tolerance, by design.
  - Signed metadata (`signed_metadata`) is not verified; documents are trusted only through transport plus the exact issuer match.
  - Metadata cache is in-process per deployment; the STATE swarm owns any shared-cache variant.
- **OA-02** (OAUTH)
  - S256 PKCE only; an issuer advertising only `plain` is reported unsupported rather than downgraded.
  - DPoP is not applied by this module; src/server/authored-oauth.ts holds the existing DPoP seam and the two are not yet joined.
  - Device poll state is returned in CompletionResult.adapterState; the command layer must persist it for the interval and slow_down backoff to hold across calls.
- **OA-03** (OAUTH)
  - CIMD revision implemented: draft-ietf-oauth-client-id-metadata-document-03 (observed 2026-09-17). The document body is produced by the existing clientMetadataDocument() in src/server/authored-oauth.ts and is not duplicated here.

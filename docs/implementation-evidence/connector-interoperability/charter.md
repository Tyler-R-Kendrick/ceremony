# Connector interoperability: working charter for implementation swarms

This document is the shared brief for every swarm working on connector interoperability in this repository. It restates the binding requirements of the task, records the seams that were actually found in the checkout, and fixes the conventions all swarms follow so that their work integrates. Read all of it before writing code. The lead integrator owns this file; propose changes through your ledger entry rather than editing it.

## 1. Execution mandate

Implement, do not propose. Design, code, integrate, test, adversarially review and validate in the same execution. Every swarm owns executable deliverables and their tests. Research supports implementation; it never substitutes for it.

Ceremony standardizes and adapts existing connector technology rather than creating an isolated ecosystem. Required first-class coverage includes Vercel Connect, Supabase integration APIs, MCP runtimes and registries, and Nango, plus the broader ecosystem in section 4. Deliver real adapters, not a catalog of nonfunctional buttons. Do not shrink required coverage into examples, documentation placeholders or future work.

The end-user surface is an embedded browser/PWA. Developer tooling may use Node, command-line tests, fixtures and local protocol doubles. An end user must never need a CLI, Docker Desktop, an extension, a local recorder or a daemon to complete ordinary hosted connector authorization. Optional local execution is a host capability with explicit availability, never a prerequisite.

Reuse existing seams and maintained upstream libraries. Keep the existing AI SDK and Workflow integration; add no competing agent framework or workflow runtime. Reviewed connector use must work with no model configured.

Do not merge someone else's pull request, force-push, publish packages, deploy production services, create paid resources, or perform real signup, provisioning, API-key creation, integration installation, connector deletion, upstream revocation, project modification or publication. A token being present in the environment is not consent to use it.

## 2. Required outcome and the core invariant

A host can discover or import a connector, inspect provenance and compatibility, bind it to approved runtime operations and credential custody, configure it safely, request appropriately scoped access, complete necessary human participation, verify the actual account/resource relationship, invoke an authorized capability, and recover or disconnect without confusing those operations.

The same service may be available through a native adapter, Vercel, Nango, Pipedream, a hosted MCP server, or a host-owned credential provider. Ceremony preserves those choices and their trust differences. It must not silently move secrets between them, substitute identities, or switch to a more privileged route when another route fails.

> An imported description is not an approved runtime binding. An approved binding is not a grant. A grant is not proof of every advertised capability. A successful transport response is not proof of the intended identity or absence of an earlier side effect.

### 3.1 Environment quirks of this execution host

- `NODE_OPTIONS` is injected with literal quotes and breaks Node. Before any `node`/`npm`/`npx` command run: `export NODE_OPTIONS="--max-old-space-size=8192"`.
- The process runs as root. `tests/fixtures/postgres.ts` now starts real PostgreSQL 18.4 under the `postgres` account when uid is 0 (`createPostgresUser`, directory ownership before `initdb`). Do not skip database tests.
- Outbound HTTPS goes through a proxy. Tests must not depend on the internet; use loopback fixture servers on ephemeral ports (`listen(0, "127.0.0.1")`).
- Run only your own test files while other swarms work: `node --import tsx --test tests/connectors/<area>/*.test.ts`. Do not run `npm test`, `npm run verify` or browser suites concurrently with other swarms (fixed ports collide). Run `npx tsc --noEmit` and `npx prettier --check <your files>` before finishing.

- **Never write a control character into a source file, not even as an escape.** Prettier rewrites a
  unicode escape such as the one for NUL or unit-separator back into the literal byte, so the file
  becomes binary on the next format run: grep then reports "binary file matches" and skips it, and
  diffs and editors mangle it. This was hit independently by two swarms. When you need an
  unambiguous composite key, length-prefix the parts (`parts.map((p) => p.length + ":" + p).join("|")`)
  rather than joining on a character that cannot appear in the data.

### 6.2 Package and responsibility boundaries

Keep independent abstractions: source record, normalized definition, runtime binding, connection, evidence, execution/lifecycle. Do not duplicate the recipe/effect infrastructure; reference or extend it. Do not turn a universal capability interface into a `fetch(url, headers, body)` escape hatch.

Directories: core contracts `src/core/connectors/`; server `src/server/connectors/{import,formats/<name>,auth,events,mcp,registries/<name>,providers/<name>,state,commands}`; tests `tests/connectors/<area>/*.test.ts` with doubles under `tests/connectors/doubles/`; fixtures under `tests/connectors/fixtures/`. Public export barrels, `package.json`, lockfile, `scripts/`, CI, root docs links, `src/server/teaching-http.ts`, `src/server/hosted/*`, `examples/*`, `src/server/mcp.ts` and `src/core/index.ts` are integrator-owned: propose patches in your ledger entry as exact diffs or as a self-contained function the integrator can mount.

### 6.3 Source integrity and versioning

Distinct version fields for envelope, native document, importer, normalized definition, adapter, API operation and evidence format. Store exact-byte source digest and separate canonical normalized digest. Record every overlay, translator version and dependency digest. Bind approval to the exact transitive artifact set and runtime policy (`RuntimeBinding.reviewedDigest`). A digest proves identity of bytes, not trust; a signature proves a signer's statement only under signer trust policy.

Refresh creates a new candidate revision; it cannot silently change an executable binding, destination, auth scope or output classification. Diff security-sensitive changes explicitly. Preserve the last approved revision where policy allows; propagate upstream deletion/deprecation without switching publisher or version.

Source identifiers and registry names are never filesystem paths. Use digests for internal keys; percent-encode path segments once; reject traversal and reserved object keys; preserve native spelling for lookup and round trips.

### 6.4 Owner, grant and target binding

Derive the actor through host authentication (`authenticatedActor`). Never accept tenant, subject, session, role, capabilities, broker account owner or workload identity as tool arguments. The connection key accounts for: host tenant + owner kind + owner identity + authority instance/environment + upstream account + client registration/issuer + auth profile + target resource/installation/project + runtime binding revision + policy/configuration revision. User, organization and workload are different owner kinds. A provider account and the host user are different identities. A Vercel project is not an organization; an OAuth issuer is not necessarily the API origin; a Supabase project user is not the Management API principal. Session-bound reuse stays scoped; durable owner connections cross sessions only through explicit host authorization.

Record requested, reported-granted and observed permissions separately. Empty scopes mean unknown or unscoped, never unlimited. Verification names the specific target and evidence type. Unknown account identity blocks flows whose intent requires an exact account match.

### 6.5 Credential and handoff interfaces

Server-only custody ports for host-owned credentials, external credential vending, external authenticated execution and attended browser references. A resolver provides a short-lived internal use operation or an opaque broker reference, never a JSON value that can enter public results. Avoid copies, body logging, raw exception retention and unintended serialization. External broker refresh remains the broker's responsibility unless its contract delegates it.

OAuth state, PKCE verifier, device codes, authorization URLs, Connect links, widget tokens and private collector references are protected transient material (`HandoffIssue.private`). Render human instructions only through `humanConnectionProjection` for the authenticated initiating human. Never inject them into model history, teaching recordings, recipe export, catalog JSON, analytics or generic browser draft storage. A vendor's claim that a link is chat-safe does not override this.

Handoffs need persisted correlation, exact trusted destination/return routing, expiry, initiating subject, intent, binding revision and one-use completion. Popup messaging validates origin, source window and correlation. Closing a window, a "Done" button or a postMessage is not success. Resume rereads authoritative state and verifies the target.

### 6.6 Policy-bound operations

An invocation names an approved connection/binding and a registered operation with validated inputs, never a URL, auth header, scopes, SQL, callback origin or credential owner. Separate effect classification from data classification and cost; the host chooses whether a capability requires confirmation. Do not infer safety from HTTP method, MCP annotations, `readOnly`, names, descriptions or model assertions. Parameters selecting a repository, workspace, table, project, account, file, bucket or recipient are checked against the connection's permitted targets. A remote tool may change behind a stable URL: pin and review description/schema changes, retain approval provenance, and keep per-call policy.

### 6.7 Lifecycle, persistence and uncertain effects

Async shared PostgreSQL in production, `SQLiteCeremonyStore` locally. No transaction spans OAuth, HTTP, inference or human participation. Persist intent before consequential calls; use command IDs, optimistic revisions, worker fencing, connection generations and the outbox. Replay-safe retries require operation-specific evidence (`BoundOperation.replay`): genuinely read-only, an upstream idempotency key with documented scope, or reconciliation proving the operation did not occur. Otherwise an interrupted mutation enters `indeterminate`; disable unsafe automatic retries in dependencies.

Fence reconnect/disconnect/revoke against refresh, invocation and delayed callbacks; reject stale callbacks for an older generation. Single-flight refresh for host-owned rotating tokens. Retry budgets and circuit breakers are per connection/authority and cannot leak status across tenants. Model local cancel, local unlink, broker deletion, upstream grant revocation, shared connector deletion and resource deprovisioning as separate effects with separate policy.

### 6.8 Safe imports and network access

Imported documents, URLs, descriptions, schemas, examples, catalogs, extensions and returned metadata are untrusted data. Never evaluate their code; never install a package, launch a container, load a Ruby connector, run a workflow or navigate a browser to import a definition.

Bounded parsing for JSON/YAML: reject duplicate keys and unsupported YAML tags, prevent prototype pollution, bound decompression, nesting, aliases, references, regex execution, schema composition, JSONPath selection, document counts and total bytes. XML requires entity expansion disabled. Parse errors must not echo embedded secrets.

Reference resolution and discovery fetches use the same SSRF controls as execution: no automatic redirects (validate every hop), reject URL userinfo, forbidden schemes, unexpected ports, IP-literal bypasses, DNS rebinding, loopback/link-local/private/metadata networks by default, and redirects crossing trust boundaries. Bind DNS checks to the actual connection (`createPublicAuthLookup`). Strip credentials across redirects; never forward a management token to an imported URL. Private enterprise endpoints require explicit administrator-approved policy and environment (`ApprovedDestination.network = "approved-private"`); tests use explicit loopback exceptions confined to fixture processes.

Separate fetching a schema from approving its declared servers or authorization server. Exact OAuth issuer comparison follows the protocol and is not URL canonicalization for display. Protect imports/uploads with host authorization, bounded multipart handling, CSRF/origin checks; raw source copies are protected artifacts with retention/deletion controls.

### 6.9 Browser and agent presentation

Ordinary path: browse/import, understand support and custody, configure missing prerequisites, connect, view verified target, use/reconnect/disconnect. Directory entries show source ecosystem, service, custody mode, runtime, configuration requirements, capabilities and evidence level; alternatives for one service are grouped, never merged. Fixture entries stay visibly separate from provider-backed and unconfigured integrations. All browser controls, HTTP routes, MCP tools and WebMCP tools use the same authenticated commands; a displayed preference must correspond to server enforcement. Stopping an assistant prevents new delegated work through every transport.

### 6.10 Compatibility and exports

Versioned `ceremony-connector` profile with distinct import, execution and export conformance reports. Legacy v1 stays supported. Never add fake authentication methods for a public API; represent no-credential explicitly. Export only descriptions and safe public requirements: no connection instances, credentials, private URLs, artifact handles, consent receipts, owner identities or hidden runtime configuration. An MCP registry export requires a real hosted MCP binding. Security-critical losses block affected execution even when the rest of the document stays discoverable.

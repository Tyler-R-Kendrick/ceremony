# Teaching delivery evidence

`verification.json` is generated by `scripts/verify-release.ts`; it is not hand-maintained. Its absence is missing evidence, not success. The strict schemas and verdict derivation live in `src/server/verification.ts`. A report binds the exact Git commit, non-secret configuration fingerprint, dependency versions, runtime/browser attempts and evidence files.

`profile.json` explicitly selects capabilities, but its deployment settings are intentionally unconfigured. An unconfigured production identity/origin profile cannot pass. Do not put credentials, access tokens, app PEMs, account identities, private links, model prompts or raw logs in this directory. The directory is excluded from package distribution.

## Evidence submission

An operator supplies `CEREMONY_VERIFICATION_RESULTS`, a JSON array of `VerificationExecution` records produced from actual command execution. Each record has the exact command, exit code, attempt number, commit, configuration digest, timestamp, environment, runtime, attempted browser versions, acceptance IDs, and existing sanitized artifact paths. This is a trusted build/operator boundary, not an API accepting publication from untrusted users. A test filename or a mentioned acceptance ID is not evidence that its full invariant passed.

All attempts for the evaluated commit/configuration must be retained. A failed attempt followed by a successful rerun does not silently become PASS. Correct the defect, create a new exact commit and rerun the affected gate. Evidence expires after seven days by default; changing commit or material configuration invalidates it immediately. The release script checks referenced artifact paths stay within the checkout, including symlink resolution.

Run `node --import tsx scripts/verify-release.ts audit` to derive the current report. The audit does not execute missing tests or manufacture results. `live` adds only an explicitly authorized signed read-only GitHub app smoke. `release` requires the full configured set. Missing local acceptance evidence is FAIL. Missing required real-provider/platform/device evidence is BLOCKED_EXTERNAL. Skipped/not-requested required gates never count as PASS.

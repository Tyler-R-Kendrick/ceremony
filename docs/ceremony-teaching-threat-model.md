# Teaching and agent trust boundaries

This document records implemented boundaries and the evidence that exercises them. It is not a production certification. Consult the release evidence for unexecuted or externally blocked gates.

## Assets and actors

Protected assets include provider credentials, callback codes/state, collection references, setup artifacts, authenticated sessions, review grants, effect authority, and continuation identities. A procedure is shareable under tenant policy; those assets are not transferred with it. Authors, reviewers, publishers, executors, workload agents, and the trusted host have different authority. A model is an untrusted proposer, never a verifier or identity provider.

The trusted computing boundary includes the authenticated application server, its configured identity adapter, encryption keys, trusted operation implementations, the intended private collector, and the user's browser. Encryption at rest does not hide plaintext from a compromised authorized server or browser. Configured model, gateway, workflow and hosted-browser operators are separate processors; minimize data before their ingress, not after logging.

External host policy checks run outside database transactions. Transactional delegation checks use the command transaction, so they cannot deadlock by recursively opening an async store transaction. A host must implement its own current policy; browser `source`, owner fields, IDs and model-written text are not authorization.

## Required negative boundaries

Strict recipe schemas reject unknown structure, executable operation definitions, prototype keys and unregistered versions. Publishing binds a specific reviewed revision and digest; a digest alone grants nothing. Pinned child publication is tenant-owned and current retirement policy is checked separately from definition integrity. Runtime artifacts require fresh compatibility and verification in the current principal, target, origin, environment and configuration context.

Private inputs and transient authorization instructions must remain excluded from agent state, demonstration events, portable definitions and telemetry. Human views may need information that agents must not receive. Native WebMCP is a transport, not extra permission. Pure snapshot reads must not poll providers. A human return starts verification, not proof of consent.

The secret-ingress guard rejects known protected formats; it cannot reliably recognize every arbitrary password in unstructured text. This feature does not require narration or attachments. Credentials belong in the private collector, never instructions to the model.

## Failure and diagnostics policy

Stop assistant prevents subsequent agent work and does not revoke provider effects. Cancel connection fences local work and does not secretly revoke upstream grants. Discard demonstration deletes teaching material, not the underlying connection or mandatory audit records. A provider request may already have happened when cancellation or revocation wins; uncertain effects require reconciliation, not automatic replay.

Disable traces, screenshots, video, HAR and arbitrary request/console capture on private authentication paths. Synthetic security tests use controlled values and bounded assertions; real provider bodies, tokens, browser profiles and decrypted stores must not become evidence artifacts. Mandatory security records retain sanitized action metadata under a separate policy from optional demonstrations.

## Remaining release boundaries

Native tools now use dedicated `/tools/*` routes rather than cookie-authenticated human action routes. Server policy records delegation before provider work; subsequent commands bind the principal/session and shared stop/expiry/revocation guards. `tests/security/teaching-http.test.ts` rejects stopped native advancement, cancellation and reconnection while retaining human cancellation. Mounted streams reauthenticate at every read; changing the authenticated session closes the stream before another event.

Capture now paginates tenant records, and timeline/deletion use demonstration-prefixed sequence cursors. `tests/security/demonstration-retention.test.ts` exercises more than 1,000 unrelated records and 1,002 selected events with audit retention. Compilation reads a bounded requested selection across pages, instead of silently limiting it to the first 100 events.

Automatic Connect selects current tenant revisions after closure/retirement and provider/profile validation. It binds only unique typed producers leading to the registered connection contract, preferring the fewest expanded leaves with stable ID tie-breaking. This creates no draft/publication, invokes no model and transfers no authors' artifacts. Ambiguous or missing procedures may use the host's trusted built-in flow; database failures propagate instead of causing replacement setup. Automatic catalog inspection has a 256-stored-revision budget and fails explicitly when exceeded; recipe limits remain 32 leaves/eight levels.

`stryker.security.config.mjs` targets owner, classification, effect-digest, verifier and generation guards. Its first executed run left a generation mutant alive because tests changed worker identity together with generation. The added same-workload reincarnation test isolates generation fencing. The subsequent executed run killed all 27 selected mutants with zero timeouts. This is focused critical-guard evidence, not whole-repository mutation coverage.

An imported node identifier matching a known credential format could reach the model despite its structural identifier schema. The regression in `tests/security/agent-identifiers.test.ts` reproduced this through the real AI SDK HTTP path. Coordinator snapshot identifiers and authoring catalog identifiers now pass the existing bounded text policy individually before SDK ingress. The fixed test observes zero outbound requests and retains no request bodies. This remains a known-format heuristic, not classification of every arbitrary string.

The legacy `registerPrivateCollector` integration is not the async teaching broker: it uses legacy UUID instances, synchronous persistence, and consume-once references without durable command recovery. Its HTTP collector now requires a host-authenticated `requestOwner` matching the grant owner; a missing adapter, handle alone, unsigned owner, foreign signed session or invalid signature fails closed. `tests/security/mcp-recipient.test.ts` exercises actual loopback HTTP with signed fixture sessions and real MCP messages. This does not establish async teaching parity: do not enable or certify production teaching MCP collection on legacy compatibility evidence. The production GitHub recovery collector uses purpose/field/operation/run/revision/principal-bound async collection with atomic consume-to-command association.

The focused regressions above use the actual encrypted local store and shared runtime, but are not evidence of distributed PostgreSQL races, deployed Workflow replay, real GitHub account certification or installed-PWA OS behavior. Those require their separately executed gates. No platform, provider or device gate may pass solely because its credentials or environment are unavailable. The original provider's external effect cannot be promised exactly once without that provider's idempotency or reconciliation support.

### Executed private-sink and injection boundaries

`tests/security/authoring-isolation.test.ts` sends a synthetic value through the mounted hosted Environment handler and then executes an agent against the actual local AI SDK HTTP transport. The authorized operation can read the private environment; model requests, safe run/status responses, demonstration/event/outbox records and encrypted SQLite bytes cannot contain that value. An adversarial draft description is not sent to authoring, and model-generated executable fields are rejected after two calls without changing or publishing the draft. `tests/agent.test.ts` additionally emits the known `advance` tool with extra permission, verifier and source arguments; strict validation rejects every request and no provider effect executes.

The browser Environment test inspects request destinations in memory: private values may appear only in the intended Environment POST, never another URL/body. It also checks console/page-error output, local/session storage and existing CacheStorage contents. The native recovery browser test separately proves its page loads no application/assistant bundle and its consumed collection disappears without entering safe event/audit state. The deliberate-failure diagnostics test checks generated attachments and reports; PWA tests check the static cache allowlist and logout transitions. These are complementary executed boundaries, not a claim that one test captures every possible sink. No third-party analytics/session-replay/crash-reporting integration is enabled here; adding one requires its own exclusion and negative transport tests before release. Arbitrary privileged host scripts can read private DOM and remain inside the trusted-browser boundary.
